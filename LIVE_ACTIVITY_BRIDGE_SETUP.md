# My Commute — Live Activity / Dynamic Island Bridge

Native Swift Widget Extension + Expo Modules bridge. **Reads the Tier 2 cache
(React Native is the single writer); never fetches or duplicates it.**

---

## What was built

### 1. Swift Widget Extension — `targets/MyCommuteWidget/`
- `MyCommuteLiveActivity.swift` — `ActivityKit` `ActivityAttributes` +
  `ContentState`, the three surfaces (Dynamic Island Compact + Expanded,
  Lock Screen / Standby), LINE_COLORS accent map (11 tube lines + Elizabeth +
  Overground), confidence softening (under ~5 min full, over → `~` prefix at
  65% opacity), branch-unknown → known content swap, and the exact meltdown /
  no-signal copy from the master plan.
- `Info.plist` — WidgetKit extension plist (`com.apple.widgetkit-extension`).
- `MyCommuteWidget.entitlements` — App Group `group.com.mycommute.app`.
- `expo-target.config.js` — `@bacons/apple-targets` config (type `widget`,
  iOS 16.2+, frameworks SwiftUI/WidgetKit/ActivityKit, App Group).

### 2. Expo Modules bridge — `modules/my-commute-live-activity/`
- `index.ts` — typed native module surface
  (`startCommuteActivity` / `updateCommuteActivity` / `endCommuteActivity` /
  `isActivityActive`).
- `ios/MyCommuteLiveActivityModule.swift` — maps the cache-shaped payload onto
  `ActivityKit`, AND mirrors a slim JSON of it into the App Group container so
  the **Widget Extension process** (which cannot call the RN bridge) can read
  the same single source of truth.
- `my-commute-live-activity.podspec`, `package.json`,
  `expo-module.config.json` — module registration.

### 3. RN integration (modified)
- `services/LiveActivityService.ts` — **rewritten** to READ `getTier2Cache()`
  and forward a flattened payload. No TfL fetch. Honest void (no activity)
  when nothing is cached. Handles `meltdown` / `no-signal` signal states.
- `services/SessionManager.ts` — calls the new `start/end/update` signatures,
  subscribes to `onTier2CachePopulated` to re-render, fires the one-time
  no-signal local push, and the recovery "Got it — …" push on signal return.
  Cleans up listeners/timers on `closeSession()`.
- `app.json` — registered `@bacons/apple-targets` + the local module.

## How data flows (single source of truth)

```
Tier2CacheManager (RN writer)
   writes App-Group MMKV  tier2:<stationId>
        │
        ▼
LiveActivityService.buildPayload()
   reads getTier2Cache()  →  flattens to LiveActivityBridgePayload
        │
        ▼
MyCommuteLiveActivityModule.start/update (Expo bridge)
   • drives ActivityKit (Dynamic Island + Lock Screen)
   • writes slim JSON mirror → group.com.mycommute.app/live-activity-mirror.json
        │
        ▼
MyCommuteWidget (separate extension process)
   reads the JSON mirror  →  renders passively
```

The widget reads the **mirror file**, not MMKV directly, to avoid coupling the
extension to `react-native-mmkv`'s serialization format. RN remains the only
writer of the cache; the bridge is the only thing that touches ActivityKit.

## Setup — adding the target to the Xcode project

The project is **Expo-managed** (Expo SDK 54, `expo-router`). The Widget
target is generated by `@bacons/apple-targets` at prebuild time, so there is
**no manual Xcode target creation** — it is CI/prebuild driven.

### Steps (run once on a Mac with Xcode 16 + CocoaPods 1.16.2+)

1. **Install deps** (already in package.json): `@bacons/apple-targets` is a
   dependency; `expo-modules-core` resolves transitively. Ensure pods are
   installed for the module:
   ```bash
   # from the frontend dir
   yarn install
   npx expo install expo-modules-core   # if not already present
   ```

2. **Prebuild the iOS project** (regenerates `ios/` with the widget target):
   ```bash
   npx expo prebuild -p ios --clean
   ```
   This reads `targets/MyCommuteWidget/expo-target.config.js`, creates the
   `MyCommuteWidget` Widget Extension target, links
   `MyCommuteLiveActivity.swift`, and copies the entitlement + Info.plist.
   The App Group is auto-mirrored from root `app.json`
   (`ios.entitlements["com.apple.security.application-groups"]`).

3. **Verify entitlements** — both the main app and the widget target must list
   `group.com.mycommute.app`. `@bacons/apple-targets` mirrors it from
   `app.json`; confirm in Xcode → Signing & Capabilities if a manual build
   is needed.

4. **Build & run**:
   ```bash
   npx expo run:ios        # or open ios/MyCommute.xcworkspace in Xcode
   ```
   Live Activities require a **physical device** (not the simulator) on
   iOS 16.2+.

### Manual fallback (if not using prebuild)
If you need to add the target by hand in Xcode:
- File → New → Target → **Widget Extension**, name `MyCommuteWidget`,
  language Swift, include ActivityKit.
- Add `MyCommuteLiveActivity.swift` + the bridge module to the target's
  Build Phases (Compile Sources).
- Set the target's **Deployment Target ≥ 16.2**.
- Enable the **App Groups** capability with `group.com.mycommute.app`.
- Add `ActivityKit.framework` to the target's Frameworks/Libraries.
- The bridge module (`modules/.../ios`) must be compiled into the **main app**
  target, not the widget (it drives ActivityKit). The widget only reads the
  JSON mirror.

## Branch-unknown → branch-known transition

- `branchKnown` is derived in RN from whether the session has a resolved
  destination (`commute_destination_id`). It is set by the direction-resolution
  agent (Priority 1–3) — **not** by this module.
- When `branchKnown` is `false`, the widget collapses to line-level arrivals
  (`Northern · 3 min`). When it flips `true`, the same `ActivityContent`
  re-renders with destination names (`Edgware · 3 min`). Because it is the
  **same Activity instance** and the same view hierarchy (only text content
  changes), there is no rebuild and no flash.
- For a true `layoutId`-style shared-element morph you would need SwiftUI
  `matchedGeometryEffect` inside the expanded region; the current approach uses
  a content-swap on the same element which satisfies "content swaps, no flash,
  no rebuild" from the spec without a second Activity instance.

## No-signal & TfL-meltdown handling (exact copy)

| State | Behaviour | Copy |
|---|---|---|
| Normal | Island + Lock Screen render cached arrivals | (destination · N min) |
| No cache (truly nothing) | Activity **not started** | honest void, no false card |
| No-signal gap | Keep last content, softened | Local push: *"Signal's patchy here — still trying. Check the platform board for now."* |
| Signal returns | Re-render (flash) | Local push: *"Got it — Edgware, 3 min"* |
| Meltdown (backend flag `tfl_global_outage`) | Low-opacity glass panel | *"TfL's systems are down — not us. Trust the platform boards for now. We're watching."* |
| Meltdown recovery | Resume | *"TfL's back. So are we. Carry on."* |

No emojis anywhere. Peer tone, not corporate.

## Fonts

Space Grotesk is **not** a system font. The widget currently uses the system
font stack (`Font.system(.body, design: .default)`). To match the RN app
exactly:
1. Add `SpaceGrotesk-Bold.ttf` (and `-Regular`) to the **widget target**
   in Xcode (Build Phase → Copy Bundle Resources).
2. Register them in the widget's `Info.plist` under
   `UIAppFonts` (`Fonts provided by application`).
3. Swap `Font.mcBody` / `Font.mcHeadline` / `Font.mcTitle` in
   `MyCommuteLiveActivity.swift` to
   `.custom("SpaceGrotesk-Bold", size: 15, relativeTo: .body)` etc.

  cleanly.
